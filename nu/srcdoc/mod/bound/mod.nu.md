# bound

## timeout

The GNU coreutils `timeout` every bound of a run takes (LaunchBound),
resolved once a run to one absolute path: JAB_TIMEOUT when it is set, the
one candidate, resolved by override-path and the launch refused naming it
and its resolution when its `--version` line names no GNU coreutils, never
a fall to discovery; else, on Windows, MSYS2's /usr/bin/timeout.exe by its
Windows path first, since Windows' own `timeout`, a pause, comes ahead of
it on PATH, then every `timeout` on PATH in order, the first whose line
names GNU coreutils taken, the launch refused naming every candidate tried
when none does. `{path, version, override}`: the path, run as a value
wherever a bound runs, so no bound resolves the name again against its
own job's PATH or working directory (ResolvedOverride, Astra's review 10,
F8); its version line; and the override as given, "" with none, which a
launch's record keeps beside the path (`timeout_override`).

## override-path

JAB_TIMEOUT as one absolute path: a value holding a separator expanded
against the launch's working directory with no symlink resolved, so an
absolute path stays as typed; a bare name resolved through PATH, its first
external; a value resolving to nothing, or to a directory, refused naming
it.

## timeout-version

The first line a `timeout` prints for --version, "" when it prints none
or will not run.

## gnu-timeout

Whether a version line is GNU coreutils' `timeout`'s.
